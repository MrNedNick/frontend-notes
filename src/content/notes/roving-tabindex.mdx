## Symptom

The booking grid renders a button for every free half-hour: five days, twelve
hours, thirty-minute slots. That is up to 120 buttons, and a keyboard user
tabbing towards the footer had to pass through all of them.

## How to reproduce

Every audit was green — focus visible, labels correct, contrast fine. Nothing
catches this except counting:

```js
[...document.querySelectorAll('a[href],button:not([disabled]),input,[tabindex]')]
  .filter((el) => el.tabIndex >= 0).length
// 130
```

## What it was not

Not a missing skip link, and not something an audit tool reports: every single
button was correct on its own. The problem is only visible in the sum.

## Cause

A grid of equivalent controls was built as a list of independent buttons, so
each one took its own place in the tab order.

## Fix

Roving tabindex: the *grid* is one tab stop, and the arrow keys move between the
things inside it. Exactly one cell carries `tabindex="0"`; the rest carry `-1` —
which is how a native `<select>`, a radio group and a menu behave.

<div class="not-prose my-6 rounded-xl border border-line bg-surface p-4 text-sm">
  <p class="font-medium">The whole mechanism</p>
  <ol class="mt-2 list-decimal space-y-1 pl-5 text-ink-soft">
    <li>One piece of state: which cell is "current".</li>
    <li><code>tabIndex</code> on each cell is <code>current ? 0 : -1</code>.</li>
    <li>A keydown handler maps arrows, Home and End to a new current cell.</li>
    <li>After the state changes, move DOM focus to that cell.</li>
  </ol>
</div>

```diff
 <button
   type="button"
+  [tabIndex]="isActiveSlot(column.date, slot.start) ? 0 : -1"
+  (keydown)="onSlotKeydown($event, column.date, slot.start)"
   (click)="book(column.date, slot.start)"
 ></button>
```

Up and down move within a day, left and right between days at the same time,
Home and End jump to the ends of a column. Focus moves *after* the attribute is
updated — in a signals-based framework, after change detection has run, so the
focus call goes in a microtask. The tab-stop count on the page went from 130 to
16.

## How not to repeat it

Count tab stops on any page with a repeated control — the one-liner above is
enough. And make the arrow keys discoverable: one line under the grid, *arrow
keys move between free slots*, is the cheapest part of the whole thing and the
one that makes it real.
